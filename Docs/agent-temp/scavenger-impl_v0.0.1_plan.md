## 0. 전제와 작업 가정

프로젝트 현황: Unity 6000.3 / URP (PC + Mobile 렌더러) / Input System 1.19 / 빈 템플릿 상태.
Meshy 에셋 파이프라인 세팅 완료 (브릿지 + MCPForUnity generate_model).

기획 미결 사항에 대한 작업 가정 (확정 아님, 프로토타입용 임시 결정):

| 미결 항목 | v0.1 가정 | 근거 |
|-----------|-----------|------|
| 시야/전장의 안개 | 도입하지 않음 | 코어 루프 검증 우선 |
| 탈출 시간 규칙 | 런 전체에 숨겨진 단일 타이머 | 가장 단순한 형태로 긴장감 검증 |
| 아웃게임 범위 | 창고(스태시) 저장만. 강화/구매 없음 | 인게임 루프 먼저 |
| 조작 방식 | 전진 자동, 좌우 이동만 입력 (원버튼 계열) | 폭탄피하기류 회피와 캐주얼 템포에 부합 |
| 시점 | 쿼터뷰 (탑다운 기울임) | 회피 + 주변 파밍 요소 시인성 |

전체 방침: 과대 시스템 금지, 그레이박스(프리미티브) 우선 진행 후 리소스 트랙에서 교체.

## 1. 마일스톤

- v0.1 그레이박스 플레이어블: 코어메카닉 트랙 완료. 큐브/캡슐로 한 판이 돌아가는 상태.
- v0.2 리소스 적용: Meshy 생성 에셋으로 교체. 플레이어/폐지/상자/장애물/탈출구.
- v0.3 환경 및 효과: 구간 환경 모듈, 라이팅, VFX, UI 폴리시.

트랙은 순차가 기본이되, 리소스 트랙(Meshy 생성은 대기시간이 김)은 v0.1 진행 중 백그라운드로 병행 가능.

## 2. 트랙 A: 코어메카닉

폴더: `Assets/Scripts/Game/` 하위에 기능별 구성. 각 폴더에 CLAUDE.md 작성 (관리 규약).

```
Assets/Scripts/Game/
  Run/        런 상태 머신, 숨김 타이머, 신호 알림, 정산
  Player/     이동(자동 전진 + 좌우), 사망 처리
  Loot/       파밍 상호작용, 인벤토리(런 한정), 가치/시간 데이터
  Segment/    구간 생성 체인, 깊이 스케일링, 선택지 노드
  Obstacle/   시한폭발형 장애물
  UI/         루팅 게이지, 가치 합계, 선택지, 알림 배너 (uGUI)
  Debug/      런 상태 대시보드 (온스크린 로그)
```

### A-1. 플레이어 이동
- 자동 전진 + 좌우 입력 (Input System). CharacterController 기반.
- 사망 시 이벤트 발행만 (연출은 트랙 C).

### A-2. 파밍 / 인벤토리
- `LootDefinition` (ScriptableObject): 가치, 상호작용 시간, 등급(tier), 요구 조건 슬롯(v0.1 미사용).
- `LootSpot` (씬 배치물): 홀드 상호작용, 진행 중 이동 시 취소.
- `RunInventory`: 런 동안의 획득 목록. 사망 시 전량 소멸, 탈출 시 스태시로 확정.

### A-3. 구간 / 선택지
- `SegmentDefinition` (ScriptableObject): 길이, 루트 테이블, 장애물 밀도.
- `SegmentSpawner`: 앞쪽으로 구간 프리팹 체인 생성, 지나간 구간 제거.
- 구간 끝 = 선택지 노드: 탈출(정산) / 전진(깊이 +1).
- 깊이 스케일링: 깊이 → 루트 테이블 tier 가중치와 장애물 밀도를 올리는 커브 (ScriptableObject 하나로 관리).

### A-4. 장애물
- v0.1은 1종: 시한폭발형. 배치 시점부터 카운트다운, 폭발 반경 내 플레이어 즉사.
- `ObstacleBase` 추상화는 하되 파생은 폭탄 하나만. (과대 설계 방지)

### A-5. 런 규칙 (시간 제한 + 비정형 정보)
- `RunController`: 숨겨진 제한 시간. 초과 시 탈출 불가 처리(사망 동일 취급, 규칙은 추후 조정).
- 신호 알림: 잔여 시간 구간(예: 50%, 80%, 95%) 통과 시 모호한 문구의 알림 이벤트 발행. 정확한 수치는 노출하지 않음.

### A-6. 정산 / 스태시
- 탈출 시 인벤토리 가치 합계를 `PlayerStash`(JSON 저장, persistentDataPath)에 누적.
- 아웃게임 화면은 텍스트 수준의 결과 패널만.

### A-7. 디버그 대시보드
- 온스크린 패널: 현재 깊이, 경과/잔여 시간(디버그에서만 실수치 노출), 인벤토리 가치, 구간 시드.
- 개발 빌드 전용 토글.

검증: 각 단계마다 /unity-cs-compile-check, 트랙 완료 시 /codex 교차 검토 (gpt-5.6-sol xhigh).

## 3. 트랙 B: 리소스

Meshy generate_model(text→3D) 기반. 생성 대기시간이 있으므로 트랙 A와 병행.

### B-1. 에셋 목록 (v0.2 대상)

| 에셋 | 수량 | 용도 | 우선순위 |
|------|------|------|----------|
| 플레이어 캐릭터 (폐지 줍는 노인/카트 컨셉) | 1 | 플레이어 | 상 |
| 폐지 더미 / 박스 | 2-3 | tier 1 루트 | 상 |
| 보물상자 / 금고 | 2 | tier 2-3 루트 | 상 |
| 시한폭탄 / 위험물 | 1 | 장애물 | 상 |
| 탈출 지점 표식 (출구/택시) | 1 | 선택지 노드 | 중 |
| 골목 소품 (전봇대, 쓰레기봉투, 펜스) | 3-5 | 환경 드레싱 (트랙 C 사용) | 하 |

### B-2. 파이프라인 규약
- 생성: generate_model (meshy-6, glb, 텍스처 포함) 또는 웹+브릿지 수동 생성.
- 정리: `Assets/MeshyImports/` 도착 → 검수 후 `Assets/Art/Models/<카테고리>/`로 이동, 프리팹화.
- 링크 문서화: `Assets/Art/CLAUDE.md`에 에셋-프리팹-사용처 매핑 기록 (에셋 관리 규약).
- 스케일/피벗 통일: 임포트 시 1유닛 기준 통일, 프리팹에서 보정.

### B-3. 교체 작업
- 그레이박스 프리팹의 메시만 교체하는 구조로 진행 (로직 프리팹과 비주얼 자식 분리).

## 4. 트랙 C: 환경 및 효과

### C-1. 환경 모듈
- 구간 프리팹용 골목/폐허 환경 모듈: 바닥, 좌우 벽(가벽), 드레싱 소품 슬롯.
- 깊이별 분위기 변화: 깊어질수록 어두워지는 라이팅 프리셋 (URP Volume 프로파일 3단계).

### C-2. VFX / 연출
- 폭탄: 카운트다운 점멸 + 폭발 파티클.
- 루팅: 진행 게이지 + 완료 이펙트.
- 탈출 신호 알림: 화면 가장자리 페이드 + 사운드 스팅어 자리만 (사운드 소스는 추후).
- 사망: 간단한 슬로우 + 페이드 아웃.

### C-3. UI 폴리시
- 인벤토리 가치 합계 상시 표시, 선택지 프롬프트(탈출/전진), 알림 배너.
- 모바일 대응 세이프 에어리어만 고려, 세부 스킨은 범위 외.

## 5. 커밋 / 문서 운영

- 트랙 A 단계(A-1..A-7)별 원자 커밋.
- 각 기능 폴더 CLAUDE.md는 해당 단계 커밋에 포함.
- 트랙 완료 시 본 문서 갱신 + 기획 문서와의 차이(가정 변경 등) 기록.
- v0.1 완료 시 본 문서를 v0.0.1_release로 승격하고 다음 버전 플랜 작성.
