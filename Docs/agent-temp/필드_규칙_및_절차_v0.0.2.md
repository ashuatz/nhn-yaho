## 1. 개요

### 1.1 개발목표

(1) 플레이어 캐릭터가 걸어다닐 수 있는 필드의 기준과 목표를 정의합니다
* 규격화된 필드의 기준으로, 파밍존의 빈도, 장애물, 오브젝트, 기믹의 규칙을 수립하는 기준이 됩니다
* 플레이어 캐릭터가 안정적으로 이동하고 상호작용할 수 있는 공간의 최소 요건을 명확히 합니다

### 1.2 개발방향

(1) 해당 기준을 바탕으로 게임의 오브젝트 규칙 등 모든 것을 정의합니다

## 2. 필드 구성 및 정의

### 2.1 필드 정의 및 구성

(1) 정의 및 구성
* 바닥은 캐릭터가 걸어다니는 땅입니다
* 실제 콜리전이 필요하므로, 실제 게임 오브젝트로 생성합니다

<!-- [이미지 삽입] 참고이미지-3번.PNG (바닥 구성 참고 이미지) -->

![참고이미지-1번](./images/참고이미지-3번.PNG)

* 필드는 다음과 같이 구성되어 있습니다

| 단위 | 크기 | 설명 |
|------|------|------|
| 블록 | 1 x 1 | 가장 작은 단위이며, 블록 하나가 1 유닛입니다 |
| 존 | 25 (길이) x 7 (너비) | 블록이 모여 만든 한 덩어리입니다 |
| 구간 | 8 (길이) x 7 (너비) <span style="color:#FF4444">(ver02 신규)</span> | 존과 존 사이를 잇는 짧은 통로이며, 탈출 지점이 놓입니다 (3.3 참고) |
| 필드 | 존 + 구간 (반복) <span style="color:#FF4444">(ver02 변경)</span> | 존 여러 개와 구간 하나가 번갈아 이어져 만들어진 전체 공간입니다 |

* 구간은 존과 같은 너비를 쓰지만 길이가 짧고, 드랍 아이템과 파밍 포인트를 배치하지 않습니다

    -> 정산 지점(탈출 지점)을 눈에 띄게 하기 위해 비워 둡니다. 구간 길이는 컬럼 값으로 정합니다 (4.2 참고)

(2) 존 구성

<!-- [이미지 삽입] 참고이미지-4번.PNG (존 구성 참고 이미지) -->

![참고이미지-4번](./images/참고이미지-4번.PNG)

* 하나의 존은 다음과 같이 구성되어 있습니다

| 요소 | 설명 |
|------|------|
| 드랍 아이템 | 플레이어 캐릭터가 이동하며 획득할 수 있는, 바닥에 놓인 루팅 아이템들입니다 |
| 파밍 포인트 | 존 양옆에 붙어 있는 공간으로, 플레이어 캐릭터가 상호작용할 수 있는 아이템 오브젝트가 설치되어 있습니다 |
| 기믹 | 플레이어 캐릭터의 생존과 이동을 방해하는 요소로, 스탯에 영향을 주거나 캐릭터를 사망시킬 수 있습니다 |

<span style="color:#888888">각 존은 절차적으로 생성되며, 존마다 드랍 아이템의 비율, 파밍 포인트의 개수, 기믹의 개수를 조절할 수 있도록 min / max 컬럼을 신설하여 밸런스를 맞출 예정입니다.</span>

<span style="color:#888888">플레이어 캐릭터가 안으로 이동할수록 난이도가 높아지므로, 스테이지(필드) 단위로 밸런스를 분리하여 관리할 예정입니다.</span>

* <span style="color:#2a9d8f">드랍 아이템 / 파밍 포인트 / 기믹 등에 대한 세부 내용은 별도 문서에서 다룹니다</span>

(3) 필드 구성 <span style="color:#FF4444">(ver02 변경)</span>
* 필드는 존과 구간이 이어진 연속된 공간이며, 끝없이 앞으로 이어집니다
* 하나의 스테이지는 <span style="color:#4488FF">**존 N개 + 구간 1개**</span>로 구성됩니다

    -> <span style="color:#888888"><sub>스테이지는 2분 30초 볼륨으로, 플레이어 캐릭터가 플레이할 수 있는 콘텐츠의 집합체입니다</sub></span>

* 하나의 스테이지는 정해진 개수 범위 안에서 존을 랜덤 수치로 생성합니다

    -> 각 존의 개수는 스테이지 진입 시 결정됩니다

* 스테이지 끝의 구간을 지나면 다음 스테이지가 시작되며, 존 개수가 다시 결정됩니다 (3.3 참고)

    -> 필드 자체가 끊기지 않으므로, 스테이지가 바뀌어도 플레이어는 계속 앞으로 걷습니다

```mermaid
flowchart LR
    A["존 1"]:::zone --> B["존 2"]:::zone --> C["... 존 N"]:::zone --> D["구간<br/>(탈출 지점)"]:::link --> E["존 1<br/>(다음 스테이지)"]:::zone --> F["..."]:::zone

    classDef zone fill:#457b9d,stroke:#345d75,color:#fff
    classDef link fill:#2a9d8f,stroke:#1f7268,color:#fff
```

<span style="color:#888888">존의 개수는 min / max 컬럼을 신설하여 밸런스를 맞출 예정입니다.</span>

* <span style="color:#2a9d8f">필드 구성의 세부 내용은 별도의 문서에서 다룹니다</span>

## 3. 존 진행 및 절차 생성

### 3.1 절차 생성

(1) 생성 방식 및 구성
* 존은 처음부터 만들어져 있지 않고, 플레이어 위치를 기준으로 앞에 나올 존을 절차적으로 생성합니다
* 각 존 안의 요소(드랍/파밍 포인트/기믹)는 정해진 수치 범위 안에서 배치됩니다

| 진행 단계 | 동작 |
|-----------|------|
| 미리 생성 <span style="color:#FF4444">(ver02 변경)</span> | 플레이어 앞으로 <span style="color:#4488FF">**전방 패딩**</span>(기본 2존) 거리만큼 미리 만들어 둡니다 |
| 지나간 존 정리 <span style="color:#FF4444">(ver02 변경)</span> | 뒤로 밀려난 존은 제거합니다. 동시에 유지되는 것은 직전 1개 + 현재 + 전방 패딩만큼입니다 |

!! 미리 생성이 1개면 존이 생겨나는 장면이 화면 안에서 보입니다. 화면에 들어오는 거리보다 멀리까지 미리 만들어야 하므로, 전방 패딩을 컬럼으로 두고 카메라 구도에 맞춰 조정합니다 (4.2 참고).

    -> 구간도 같은 규칙으로 미리 생성됩니다 (존과 구간을 구분하지 않고, 앞으로 패딩 거리만큼 채웁니다)

(2) 난이도 구성

| 항목 | 규칙 |
|------|------|
| 스테이지 진행 | 스테이지마다 존 개수와 드랍 등급, 기믹 개수, 파밍 포인트 개수 등을 수정할 수 있습니다 |
| 봉쇄 방지 | 통과 불가능한 배치가 나오지 않도록 기믹 오브젝트 간의 간격 및 수치를 정할 수 있도록 합니다 |

### 3.2 존 제거 시스템

(1) 도입 이유
* 한 존에 플레이어 캐릭터가 오래 머물 경우, 캐릭터가 있는 위치를 기준으로 뒤쪽 바닥을 제거합니다
* 뒤쪽 바닥이 사라지면 되돌아갈 수 없으므로, 플레이어가 계속 앞으로 나아가도록 강제하기 위함입니다

(2) 제거 시점의 기준
* 플레이어 캐릭터의 현재 위치를 기준으로 삼습니다
* 캐릭터 위치에서 몇 칸 뒤부터 제거할 것인지를 수치로 입력하여 정합니다

    -> 이 수치만큼 뒤쪽에 여유를 두고, 그보다 더 뒤에 있는 바닥이 제거 대상이 됩니다

(3) 제거 방식
* 제거가 되는 영역은 다음과 같은 상태를 가집니다

```mermaid
flowchart LR
    A["정상"]:::keep --> B["제거 예정"]:::warn --> C["제거"]:::gone

    classDef keep fill:#457b9d,stroke:#345d75,color:#fff
    classDef warn fill:#e9c46a,stroke:#c9a84a,color:#333
    classDef gone fill:#6c757d,stroke:#495057,color:#fff
```

| 상태 | 설명 |
|------|------|
| 정상 | 플레이어 캐릭터가 밟을 수 있는 공간입니다 |
| 제거 예정 | 바닥이 흔들립니다. 이때 흔들리는 시간을 별도 컬럼으로 정의할 수 있습니다 |
| 제거 | 해당 영역의 바닥이 땅으로 떨어지는 애니메이션 연출을 재생합니다 |

### 3.3 스테이지 인계와 탈출 지점 <span style="color:#FF4444">(ver02 신규)</span>

(1) 구간의 역할

* 구간은 스테이지의 마지막 존 뒤에 붙는 짧은 통로이며, 두 가지 역할을 합니다

| 역할 | 설명 |
|------|------|
| 정산 지점 | 탈출 지점(웨이포인트)이 놓입니다. 밟으면 즉시 탈출하여 획득물을 확정합니다 |
| 스테이지 경계 | 구간을 통과하면 다음 스테이지가 시작됩니다 (깊이 +1) |

* 구간에는 드랍 아이템, 파밍 포인트, 기믹을 배치하지 않습니다

    -> 정산 여부를 판단하는 구간이므로 다른 선택 요소를 두지 않습니다

(2) 탈출과 진행

* 탈출 지점은 <span style="color:#4488FF">**하나만**</span> 배치하며, 밟으면 자동으로 탈출(정산)합니다

    -> 선택 인터페이스는 두지 않습니다. 밟는 행위 자체가 선택입니다

* 계속 진행하는 것은 별도의 오브젝트가 아닙니다. 탈출 지점을 밟지 않고 지나가면 그대로 다음 스테이지입니다

| 플레이어 행동 | 결과 |
|---------------|------|
| 탈출 지점을 밟는다 | 탈출 (정산 후 런 종료) |
| 밟지 않고 지나간다 | 다음 스테이지 진입 (깊이 +1, 존 개수 재결정) |

* 탈출 지점은 직진 동선에서 벗어난 위치(화면 위쪽)에 배치합니다

    -> 계속 진행하려는 플레이어가 실수로 밟아 강제 정산되지 않게 합니다

```mermaid
flowchart LR
    A["구간 진입"]:::start --> B{"탈출 지점을<br/>밟았는가?"}:::cond
    B -->|밟음| C["탈출 - 정산"]:::out
    B -->|지나감| D["다음 스테이지<br/>(깊이 +1)"]:::go

    classDef start fill:#457b9d,stroke:#345d75,color:#fff
    classDef cond fill:#e9c46a,stroke:#c9a84a,color:#333
    classDef out fill:#2a9d8f,stroke:#1f7268,color:#fff
    classDef go fill:#e76f51,stroke:#c9553a,color:#fff
```

* 스테이지가 바뀌어도 월드를 다시 만들지 않습니다. 앞쪽 존이 계속 생성되며 뒤쪽은 계속 제거됩니다

    -> 플레이어 입장에서는 끊김 없이 한 방향으로 계속 걷는 흐름입니다

(3) 제한 시간과 런 종료

* 필드가 끝없이 이어지므로, 런을 끝내는 조건은 다음 세 가지뿐입니다

| 조건 | 결과 |
|------|------|
| 탈출 지점을 밟음 | 성공 - 획득물을 확정합니다 |
| 낙사 (바닥 제거에 휩쓸림) | 실패 - 획득물 전량 손실 |
| 제한 시간 초과 | 실패 - 획득물 전량 손실 |

* 제한 시간(2분 30초)은 곧 "언제까지 탈출할지"의 압박이며, 초과하면 그 시점에 런이 실패로 끝납니다

<span style="color:#888888">(제한 시간 초과 시의 처리는 현재 구현 기준으로 기재했습니다. 시간이 다 되면 탈출 지점을 폐쇄하고 붕괴를 가속하는 방식 등 다른 안을 쓸지 확인이 필요합니다)</span>

## 4. 컬럼 정리

지금까지 문서에서 다룬, 밸런스 조절을 위해 신설할 컬럼(수치 값)을 정리합니다.

### 4.1 컬럼 구조

* 컬럼은 큰 단위에서 작은 단위로 내려가며 값을 정하는 구조입니다
* 게임의 최대 스테이지 개수를 정하고, 스테이지 안 존 개수를 정하고, 존 안의 드랍 / 파밍 포인트 / 기믹 개수를 정합니다

```mermaid
flowchart TD
    A["게임\n최대 스테이지 개수"]:::game --> B["스테이지\n존 개수"]:::stage --> C["존\n드랍 / 파밍 포인트 / 기믹 개수"]:::zone

    classDef game fill:#e76f51,stroke:#c9553a,color:#fff
    classDef stage fill:#457b9d,stroke:#345d75,color:#fff
    classDef zone fill:#2a9d8f,stroke:#1f7268,color:#fff
```

### 4.2 컬럼 목록

* 컬럼은 두 개의 시트로 나누어 관리합니다

    -> 스테이지 시트 = 각 스테이지 인덱스와 스테이지 단위 값을 정의합니다

    -> 존 시트 = 각 존 인덱스와 존 단위 값을 정의합니다

* 시트 간 연결점은 같은 색으로 표시합니다

    -> <span style="color:#4488FF">스테이지 인덱스</span>는 파란색, <span style="color:#2a9d8f">존 인덱스</span>는 초록색으로 통일합니다

    -> 존 시트의 <span style="color:#4488FF">스테이지 인덱스</span> 컬럼은 파란색으로 표시되어, 스테이지 시트와 이어지는 연결점임을 나타냅니다

(1) 스테이지 시트

| 컬럼 | 값 형태 | 설명 |
|------|---------|------|
| <span style="color:#4488FF">스테이지 인덱스</span> | 값 | 각 스테이지를 구분하는 고유 번호 |
| 존 개수 | min / max | 스테이지 안에 생성할 존의 개수 범위 |
| <span style="color:#4488FF">**구간 길이**</span> <span style="color:#FF4444">(ver02 신규)</span> | 값 | 스테이지 끝 구간의 길이 (블록). 기본 8 |
| <span style="color:#4488FF">**전방 패딩**</span> <span style="color:#FF4444">(ver02 신규)</span> | 값 | 플레이어 앞으로 미리 생성할 거리 (존 개수 단위). 기본 2 |
| 바닥 제거 시작 거리 | 값 | 캐릭터 위치에서 몇 칸 뒤부터 바닥을 제거할지 |
