## 1. 개요

### 1.1 배경

* 현재 구현은 파밍 포인트를 존 옆에 **같은 높이(flush)** 로 붙인다
* [파밍 아이템 및 포인트 시스템 문서](./파밍_아이템_및_포인트_시스템_v0.0.2.md) 2.4 (1)이 단차를 R&D 항목으로 표시해 두었기 때문에, 그레이박스는 평면으로 두고 형태 결정을 아트 프로토로 미룬 상태였다
* 사용자 확인 결과 의도는 **좌우 평면 배치가 아니라 계단으로 오르내리는 구조**이며, 씬에서 볼 때 3층으로 읽혀야 한다

### 1.2 개발목표

(1) 파밍 포인트를 본선과 다른 높이에 두고 계단으로 연결합니다

* 화면에서 위/아래로 층이 갈라져 공간의 깊이가 읽히게 합니다

(2) 점프 없이 이동 조작만으로 오르내릴 수 있게 합니다

    -> 조작은 이동뿐이므로 (파밍 문서 2.6 (1)) 계단이 통과 가능한 수치여야 합니다

(3) 층 구조가 본선 발판을 가리지 않게 합니다

    -> 카메라 쪽으로 올라가는 지형은 시야를 막습니다. 방향 규칙은 2.2에서 정합니다

## 2. 목표 구조

### 2.1 3층 정의

* 본선(존)을 기준층으로 두고, 파밍 포인트가 위/아래 층을 만듭니다

| 층 | 대상 | 높이 | 화면 위치 |
|------|------|------|-----------|
| 상층 | 파밍 포인트 (상단) | 본선 + 단차 | 화면 위쪽 |
| 기준층 | 존 본선 (보행로) | y = 0 | 화면 중앙 |
| 하층 | 파밍 포인트 (하단) | 본선 - 단차 | 화면 아래쪽 |

* 한 존에 상단/하단이 하나씩 배치되면 화면에 3층이 동시에 보입니다

    -> 배분 규칙(1번째 상단 / 2번째 하단 / 3번째부터 랜덤)은 이미 구현되어 있습니다 (파밍 문서 2.5)

### 2.2 화면 방향 근거

* 카메라는 아이소 고정 회전(pitch 30 / yaw -45)입니다 (ADR-0008)
* yaw -45에서 카메라 전방은 약 (-0.61, -0.5, 0.61)이고, 카메라는 룩앳에서 전방 반대로 물러나므로 **+x 쪽에 위치**합니다
* 따라서 화면 방향은 다음과 같이 확정됩니다

| 월드 축 | 카메라 기준 | 화면 | 파밍 포인트 타입 | 단차 |
|---------|-------------|------|------------------|------|
| -x | 먼 쪽 | 위 | 상단 | 올라감 (+y) |
| +x | 가까운 쪽 | 아래 | 하단 | 내려감 (-y) |

* 이 배정은 현재 코드와 이미 일치합니다

    -> FieldSpawner.FarmingPoints의 `sideSign = Top ? -cameraSide : cameraSide`

    -> 즉 **좌우 배정은 그대로 두고 높이(y)만 추가**하면 됩니다

* 카메라 쪽(+x)이 내려가야 하는 이유는 배경 지형과 같습니다. 카메라 쪽에 솟는 지형을 두면 본선 발판이 가려집니다

    -> 배경도 같은 근거로 카메라측을 계단식 하강으로 만들고 있습니다 (SegmentEnvironment.AddTerracedDescent)

### 2.3 진입 동선

* 소켓(입구)은 본선과 같은 높이(y = 0)에 유지합니다

    -> 소켓은 존과 파밍 포인트의 접점이자 제거 판정 기준이므로 기준층에 남깁니다 (파밍 문서 2.7 (1))

* 소켓에서 플랫폼까지 계단이 연결됩니다

| 구간 | 높이 | 역할 |
|------|------|------|
| 소켓 (입구) | y = 0 | 본선에서 진입하는 지점 |
| 계단 | 0 -> 단차 | 오르내리는 구간 |
| 플랫폼 | 단차 | 아이템 오브젝트가 놓이는 평면 |

* 입구 외 구간은 막아도 됩니다 (파밍 문서 2.6 (2)) - 계단이 유일한 동선이 되면 진입 유도가 명확해집니다

## 3. 계단 규격

### 3.1 캐릭터 제약

* 플레이어는 CharacterController이며 현재 값은 다음과 같습니다 (Assets/Prefabs/Player.prefab)

| 항목 | 값 | 의미 |
|------|-----|------|
| Step Offset | 0.3 | 이 높이 이하의 단은 걸어서 올라간다 |
| Slope Limit | 45 | 이 각도 이하의 경사는 걸어서 올라간다 |
| Height / Radius | 1.6 / 0.35 | 캡슐 크기 |

!! 계단 한 단(riser)이 Step Offset을 넘으면 점프가 없는 이 게임에서는 통과 불가 지형이 됩니다.

### 3.2 권장 수치

* 아래는 착수 기준값이며, 플레이 확인 후 조정합니다

| 항목 | 값 | 근거 |
|------|-----|------|
| 단 높이 (riser) | 0.25 | Step Offset 0.3에 여유 0.05 |
| 단 깊이 (tread) | 0.5 | 캡슐 반경 0.35보다 크게 - 발판에 안정적으로 서진다 |
| 총 단차 | 1.0 (4단) | 3층이 눈에 읽히는 최소 높이 |
| 계단 길이 | 2.0 | 4단 x 0.5 |
| 유효 경사 | 약 26.6도 | Slope Limit 45 이내 |

<span style="color:#888888">총 단차는 1.0 / 1.25 / 1.5를 플레이에서 비교해 확정합니다. 높을수록 층 구분이 명확하지만 계단이 길어져 파밍 포인트 크기(4~7블록)를 잠식합니다.</span>

### 3.3 콜라이더 구성 권고

* 시각은 계단, **충돌은 경사로(ramp)** 로 구성하는 것을 권장합니다

| 방식 | 장점 | 단점 |
|------|------|------|
| 계단 시각 + 경사로 콜라이더 (권장) | 이동이 매끄럽고 CC 떨림이 없다 | 시각과 충돌이 분리되어 관리 필요 |
| 계단 콜라이더 그대로 | 구성이 단순하다 | 단마다 CC가 튀어 오르며 카메라가 흔들린다 |

    -> Step Offset 경계에서 CharacterController는 한 단씩 올라갈 때 수직으로 튀어 오릅니다. 계단이 4단이면 그 진동이 4번 반복되어 이동감이 나빠집니다

    -> 경사로 콜라이더는 계단 대각선을 덮는 얇은 박스 하나로 충분합니다 (각도 26.6도)

## 4. 코드 변경 지점

* 파일별로 무엇을 바꿔야 하는지 정리합니다. 좌우 배정 로직은 건드리지 않습니다

### 4.1 필수 변경

| 파일 | 변경 내용 |
|------|-----------|
| Field/ZoneDefinition.cs | 파밍 포인트 단차 컬럼 추가 (farmingPointRiseBlocks 등) |
| Field/FarmingPoint.cs | 플랫폼 높이 보유 + 안전지대 XZ 범위에 계단 구간 포함 |
| Field/FieldSpawner.FarmingPoints.cs | 상단은 +단차, 하단은 -단차로 배치. 그레이박스 폴백에 계단 생성 |
| Editor/FieldPrefabTemplates.cs | 프리팹 템플릿에 계단 + 층 높이 반영 (상단/하단 형태 분리) |

### 4.2 확인 후 조정

| 파일 | 확인 사항 |
|------|-----------|
| Field/FarmingPoint.cs | 구역 위 판정(IsPlayerOverPlatform)이 계단 구간을 포함하는지 - 빠지면 계단에서 경계가 풀려 옆으로 끌려간다 |
| Field/FieldSpawner.cs | 배경 블록 제외 영역(RecordFootprint)에 계단 길이를 더해야 한다 |
| Player/PlayerController.cs | 낙사 임계 y < -4. 하층 깊이가 이 값에 가까워지면 안 된다 (3.2 기준 -1.0은 안전) |
| GameFlow.cs | RecoverPlayerIfFallen이 y < -0.5에서 발동한다. 런 시작 시점에만 돌지만, 하층에서 재시작하는 경로가 생기면 오작동 여지 |

### 4.3 손대지 않는 것

* 상단/하단 배분 규칙 (파밍 문서 2.5) - 이미 구현됨
* 좌우 배정 (Top = -x / Bottom = +x) - 2.2에서 확인한 대로 이미 맞다
* 소켓 기준 제거(흔들림 -> 낙하) - 층이 생겨도 판정 기준은 소켓 좌표 그대로

## 6. 검증 체크리스트

* 작업 후 플레이에서 확인할 항목입니다

| 항목 | 기대 결과 |
|------|-----------|
| 씬 외관 | 상층 / 본선 / 하층이 화면에서 3층으로 구분된다 |
| 상단 진입 | 이동 조작만으로 계단을 올라간다 (걸리거나 튀지 않는다) |
| 하단 진입 | 이동 조작만으로 계단을 내려간다 (낙하로 처리되지 않는다) |
| 계단 위 경계 | 계단 중간에서 옆으로 밀려나거나 클램프가 풀리지 않는다 |
| 안전지대 | 플랫폼 끝으로 밀어도 떨어지지 않는다 |
| 낙사 | 하층에 서 있어도 사망하지 않는다 |
| 제거 | 소켓이 기준선에 닿으면 계단과 플랫폼이 함께 흔들리고 낙하한다 |
| 시야 | 상층(화면 위)이 본선 발판을 가리지 않는다 |
| 배경 | 럽블이 계단/플랫폼을 관통하지 않는다 |

## 7. 리스크와 제약

| 리스크 | 영향 | 대응 |
|--------|------|------|
| CC 단 오르기 떨림 | 이동감 저하, 카메라 흔들림 | 경사로 콜라이더 (3.3) |
| 계단이 파밍 포인트 크기를 잠식 | 플랫폼이 좁아져 오브젝트 배치 공간 부족 | 총 단차를 1.0부터 시작해 확인 |
| 상층이 시야를 가림 | 본선 발판 은폐 | 상층은 화면 위(-x)로 고정 (2.2), 필요 시 높이 하향 |
| 하층이 포그에 잠김 | 아이템 오브젝트 식별 저하 | LUT 하이트 포그 수치와 함께 튜닝 |
| 아트 규격 변경 시점 | 이미 전달한 규격서와 불일치 | 착수 전 아트 문서 ver02 개정 (5장) |

* 높이 구조는 방금 도입된 LUT 하이트 포그와 직접 상호작용합니다

    -> 하층이 포그에 잠기고 상층이 드러나는 룩은 의도적으로 활용할 수 있는 요소입니다. 다만 식별성이 떨어지면 파밍 포인트의 목적을 해칩니다

## 8. 착수 순서

* 다음 세션에서 이 순서로 진행합니다

| 순서 | 작업 | 산출 |
|------|------|------|
| 1 | ZoneDefinition에 단차 컬럼 추가 | 수치를 인스펙터에서 조정 가능 |
| 2 | 그레이박스 계단 + 층 생성 (폴백 경로) | 프리팹 없이도 3층이 보인다 |
| 3 | FarmingPoint 경계에 계단 구간 포함 | 계단에서 클램프가 유지된다 |
| 4 | 프리팹 템플릿(상단/하단)에 계단 반영 | 아트 다듬기 대상 확정 |
| 5 | 배경 제외 영역에 계단 길이 반영 | 관통 없음 |
| 6 | 플레이 검증 (6장 체크리스트) | 단차 수치 확정 |
| 7 | 아트 문서 ver02 개정 | 발주 가능 상태 |

* 1~3번까지가 "3층으로 보이고 오르내려진다"의 최소 범위입니다

    -> 4번 이후는 아트 전달과 룩 정리 단계이므로, 1~3번 검증 후에 진행하는 것이 안전합니다

## 9. 구현 결과 (ver02)

### 9.1 추가 요구사항

* 계획 수립 이후 다음 요구가 추가되어 함께 반영했습니다 (사용자 지시)

| 항목 | 내용 |
|------|------|
| 구역 길이 | 파밍 포인트를 z 방향으로 더 길게 만든다 |
| 입구/출구 분리 | 입구와 출구를 나누고, 출구는 z+ 쪽에 둔다 |

* 즉 파밍 포인트는 "들어갔다 되돌아 나오는 주머니"가 아니라 **앞으로 통과하는 우회로**가 됩니다

    -> 뒤쪽 바닥이 계속 제거되는 필드 규칙과 맞습니다. 되돌아 나오는 구조는 되돌아갈 수 없다는 규칙과 충돌합니다

### 9.2 확정 수치

* ZoneDefinition의 파밍 포인트 컬럼 기본값입니다 (인스펙터에서 조정)

| 항목 | 값 (블록) | 비고 |
|------|-----------|------|
| 플랫폼 깊이 (x) | 5 | 계단을 제외한 평면 구간 |
| 계단 길이 (x) | 2 | 존 가장자리에서 플랫폼까지 |
| 전체 깊이 (x) | 7 | 계단 + 플랫폼 (안전지대 x 범위) |
| 구역 길이 (z) | 9 | 입구 게이트 + 본체 + 출구 게이트 |
| 게이트 길이 (z) | 2 | 계단이 놓이는 구간, 앞뒤 각각 |
| 총 단차 (y) | 1.0 | 상단 +1.0 / 하단 -1.0 |
| 단 높이 (riser) | 0.25 (자동) | 단차 / 단 개수. 0.25 이하로 자동 분할 |
| 유효 경사 | 약 26.6도 | Slope Limit 45 이내 |
| 존당 개수 | 1 ~ 2 | 구역이 길어져 25블록 존에는 2개까지 |
| 최소 간격 | 10 | 구역 길이 9 + 여유 |

<span style="color:#888888">구역이 길어진 만큼 존당 개수 상한을 3에서 2로 내렸습니다. 3개를 넣으려면 존 길이나 최소 간격을 함께 조정해야 합니다.</span>

### 9.3 구조

| 구간 | x (존 가장자리 기준) | y | 역할 |
|------|----------------------|-----|------|
| 입구 계단 | 0 ~ 2 (z- 게이트) | 0 -> 단차 | 본선에서 올라가거나 내려간다 |
| 출구 계단 | 0 ~ 2 (z+ 게이트) | 단차 -> 0 | 본선으로 되돌아간다 |
| 차단 매스 (시각) | 0 ~ 2 (게이트 사이) | 본선 ~ 단차 | 존 가장자리와 플랫폼 사이를 메운다 |
| 차단 콜라이더 (비시각) | 0 ~ 2 (게이트 사이) | 아래층 ~ 위층 + 1.8 | 계단이 유일한 동선이 되게 막는다 |
| 플랫폼 | 2 ~ 7 (전 구간) | 단차 | 아이템 오브젝트가 놓인다 |

* 차단 매스는 상단에서는 벽(본선 위로 솟음), 하단에서는 본선과 같은 높이의 상판이 됩니다

    -> 카메라 쪽(하단)에 솟는 구조물을 두면 본선 발판이 가려지므로, 하단은 위로 쌓지 않습니다 (2.2와 같은 근거)

* 시각 매스만으로는 양쪽 다 계단을 우회할 수 있습니다 (Codex 검토 지적)

    -> 하단은 본선에서 상판으로 걸어 나가 플랫폼으로 뛰어내릴 수 있고, 상단은 플랫폼에서 본선으로 뛰어내릴 수 있습니다

    -> 그래서 시각 매스 위에 **보이지 않는 차단 콜라이더**를 캐릭터 키 이상 높이로 세웁니다. 카메라측 시야를 막지 않으면서 동선을 계단으로 고정하는 유일한 방법입니다

### 9.4 코드 반영 지점

| 파일 | 반영 내용 |
|------|-----------|
| Field/ZoneDefinition.cs | 파밍 포인트 컬럼 신설 (깊이 / 길이 / 게이트 / 단차 / 계단 길이) |
| Field/FarmingPoint.cs | Layout 구조체로 규격 주입. 소켓 2개(입구/출구), 플랫폼 높이 보유 |
| Field/FieldSpawner.FarmingPoints.cs | PointMetrics로 치수 계산 일원화. 계단 + 플랫폼 + 차단 매스 생성 |
| Field/PointSocket.cs | PointSocketRole(Entry / Exit) 신설 |
| Editor/FieldPrefabTemplates.cs | 프리팹 템플릿을 3층 구조로 개정 + 재생성 메뉴 |
| Field/FieldSpawner.cs | 배경 제외 영역(RecordFootprint)에 계단 길이 포함 |

* 계단 충돌은 계획 3.3대로 **경사로 콜라이더 1개**이고, 단 큐브의 콜라이더는 걷어냅니다

* 제거 판정 기준이 소켓 2개로 나뉘었습니다

| 판정 | 기준 소켓 | 이유 |
|------|-----------|------|
| 흔들림 시작 | 입구 소켓 (z-) | 뒤쪽부터 경고가 오는 것이 자연스럽다 |
| 낙하 | 출구 소켓 (z+) | 구역이 길어져, 입구 기준으로 떨어뜨리면 출구 쪽 플랫폼에 서 있는 동안 발밑이 무너진다 |

!! 기존 프리팹(FarmingPoint_Top / _Bottom)은 평면 규격이라, 메뉴 **Scavenger > Rebuild Farming Point Prefabs**로 재생성해야 3층 구조가 보입니다. EnsureFieldPrefabs는 있는 프리팹을 덮어쓰지 않습니다.
